{# ---------------------------------------------------- enveloppe #}

Enveloppe HTTP

Ce qui arrive sur votre endpoint

POST {base_url}{attendance_endpoint}
     https://rh.example.com/api/v1/attendance

Content-Type:  application/json
Authorization: Bearer <token>

L'authentification est configurable par service : aucune, Bearer, clé d'API (le jeton nu dans l'en-tête que vous nommez) ou Basic. Le nom de l'en-tête est paramétrable, et des en-têtes supplémentaires peuvent s'ajouter.

Codes acceptés comme succès : 200, 201, 202. Tout le reste renvoie le lot en file de reprise.

{# ------------------------------------------------------- formes #}

Deux formes de corps, pas une de plus

La branche dépend de la taille du lot

Le récepteur en service n'aiguille que sur is_object ou is_array. L'émetteur s'y conforme exactement.

Lot d'un seul pointage

{ … }

L'objet nu. C'est le cas normal : une passe par minute, et deux personnes badgent rarement dans la même minute.

Lot de deux et plus

[ { … }, { … } ]

Un tableau racine, à parcourir. La bascule se fait à deux, pas à trois.

Jamais d'enveloppe

{"attendances": [...]} ne sera jamais envoyé, et ne doit jamais être attendu. json_decode en ferait un objet : le récepteur partirait dans sa branche « un seul pointage », y chercherait timestamp et external_user_id qui n'y sont pas, n'insérerait rien — et répondrait quand même 200.

Le lot entier disparaîtrait sans trace. Le dépôt a déjà fait l'aller-retour sur cette forme ; elle est aujourd'hui verrouillée par des tests.

{# ------------------------------------------------------- champs #}

Champs

Douze clés, les mêmes dans les deux formes

ChampTypeSens
log_id entier Clé du pointage côté tm20_server. Stable — utilisable comme clé d'idempotence.
terminal_sn chaîne Numéro de série du terminal émetteur.
enrollid entier ID d'enrôlement interne au terminal. Unique par terminal seulement, jamais globalement. 0 = événement de porte.
external_user_id chaîne · null Matricule de l'agent dans votre système. null uniquement pour un événement de porte.
user_name chaîne Nom connu du serveur, ou User#<enrollid>. Pour l'enquête humaine, pas pour l'appariement.
timestamp ISO 8601 Heure murale du terminal, offset du site inclus.
mode entier Moyen de vérification : 0/1 empreinte, 2 mot de passe, 3 carte, 8 visage, 13 QR code.
inout entier 0 entrée, 1 sortie. Dérivé par le serveur.
event entier 0 normal, 1 à 4 touches F1 à F4.
temperature décimal · null Température relevée, si le terminal en remonte une.
access_granted booléen Décision d'accès du serveur au moment du pointage.
metadata objet Trame telle que le terminal l'a émise — inout mis à part.
{# -------------------------------------------------------- règles #}

Trois règles qui coûtent cher si on les lit mal

Chacune a déjà produit un incident

Règle · sens de passage

inout porte la même valeur aux deux niveaux

Le terminal émet toujours inout: 0 : la spec réserve ce champ au couple lecteur maître / lecteur esclave. C'est donc le serveur qui tient le sens de passage, par alternance bornée à la journée civile du site — le premier pointage d'un jour est toujours une entrée, de sorte qu'une sortie oubliée laisse une journée à un seul pointage au lieu de décaler d'un cran tout l'historique suivant.

La racine et metadata portent cette valeur dérivée, identiques. Auparavant metadata.inout recopiait le 0 du terminal : le même pointage se lisait « entrée » ou « sortie » selon le niveau ouvert, et une sortie lue dans metadata se comptait comme une entrée sans rien pour le signaler. Voir log_id: 2 dans l'exemple ci-dessus — 1 aux deux niveaux.

Règle · horodatage

timestamp est l'heure de l'écran, pas de l'UTC

La base stocke de l'UTC, mais le corps porte l'heure murale du terminal avec l'offset du site — +01:00, Africa/Kinshasa. C'est l'heure que l'agent a lue sur l'écran en badgeant. Un récepteur qui fait new DateTime($data->timestamp)->format('H:i:s') lit les chiffres littéralement et tombe juste, sans rien convertir.

metadata.time est l'horodatage brut du terminal, sans fuseau. Ne pas s'en servir pour dater quoi que ce soit : c'est timestamp qui fait foi.

Règle · appariement

Sans external_user_id, le pointage ne part pas

external_user_id est le seul identifiant qui ait un sens dans votre système. enrollid ne le remplace pas : c'est un compteur interne au terminal, il se recycle, et deux terminaux attribuent le même enrollid à deux personnes différentes. Le couple terminal_sn + enrollid identifie bien la ligne, mais il n'identifie pas un agent dans votre référentiel.

Un pointage dont l'agent n'a pas de matricule n'est donc pas émis. Vous ne verrez jamais de chaîne vide dans ce champ, et ne le verrez à null que pour un événement de porte.

SituationComportement
Agent avec matricule renseigné émis
Agent connu, matricule absent écarté · reste en attente
Enrôlement inconnu du serveur écarté · reste en attente
Événement de porte (enrollid 0) émis · matricule null

Écarté ne veut pas dire perdu : le pointage reste en attente en base. Le jour où le matricule est renseigné sur l'agent, la passe suivante l'emporte sans reprise manuelle, horodatage d'origine compris.

Le filtre est délibéré. Émis quand même, ces pointages recevaient un 200 sans que le récepteur ait rien enregistré faute de matricule, et basculaient « synchronisé ». Ils comptaient pour transmis d'un côté et n'existaient pas de l'autre — la perte silencieuse exacte que le reste de cette chaîne s'emploie à éviter. 

WARNING  3 pointage(s) ecarte(s), matricule (external_id) absent --
         non rattachables cote API RH : ZYTJ20128568#12, ZYTJ20128568#31

Les événements de porte échappent à la règle : aucun agent n'est en cause et aucun matricule ne leur viendra jamais, donc les retenir les laisserait en attente pour toujours.

{# -------------------------------------------------------- cycle #}

Cycle de vie et reprise

Ce qui se passe après votre réponse

Chaque pointage passe d'en attente à envoyé, ou à échec après épuisement des tentatives. En cas d'échec HTTP, le lot repart avec un délai croissant — 1, 5, 15, 60 puis 240 minutes. Au-delà de cinq tentatives le pointage bascule en échec et attend une relance manuelle.

Un pointage écarté faute de matricule ne suit pas ce cycle : il n'a pas été émis, donc il ne compte pas comme un échec. Son compteur de tentatives reste à zéro et il demeure en attente.

Ce qu'on attend de vous

Un 200 vaut acquittement : le serveur n'inspecte pas le corps de votre réponse pour décider du statut. Un récepteur qui rejette une ligne doit le signaler par un code HTTP — sinon la ligne est perdue en silence, des deux côtés.
